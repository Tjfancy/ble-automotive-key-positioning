## 版本 B：详细版（适合项目经历 + 技能关键词）

**BLE 数字钥匙定位技术原型与算法评估**（个人项目）

*无线定位与阵列信号处理*
- **RSSI 测距与定位**：用 bleak 实现 BLE 广播扫描与 RSSI 采集（5 个距离位置 × 80 样本）；拟合对数距离路径损耗模型得到路径损耗指数 n=3.0 与 1m 参考值 A=-39.5 dBm（R²=1.00）；实现三锚点最小二乘三边定位；基于 filterpy 构建 1D 恒速模型卡尔曼滤波器对距离序列平滑，平均定位误差从 0.99 m 降至 0.62 m（-36.9%），P90 误差降低 41.8%

- 无额外硬件约束下用合成数据跑通全链路，具备真实 BLE 实验能力（nRF Connect + bleak）

*技术栈*：Python, numpy, scipy, matplotlib, bleak, filterpy, BLE, AoA, MUSIC, ESPRIT, 卡尔曼滤波, 最小二乘

## 版本 C：面试口头讲述版（30 秒电梯演讲）

> 我做了一个汽车数字钥匙 BLE 定位的完整原型。
> **硬件上**，用手机 nRF Connect 广播、电脑 bleak 扫描，在 1~5 米采集 RSSI；**算法上**，先拟合对数距离路径损耗模型做测距，再用三边定位解算坐标，最后用卡尔曼滤波平滑——把平均定位误差从 0.99 米压到了 0.62 米。
> 同时我纯软件仿真了 BLE AoA，复现了 MUSIC 和 ESPRIT 两个经典算法，跑了 27 组蒙特卡洛实验，量化了 SNR 和阵元数对测角精度的影响，比如阵元从 4 个加到 16 个，在低信噪比下测角误差能从 2.7 度降到 0.3 度。
> 所有代码、图表和结论都整理在 GitHub 仓库里，可以直接讲。

## 面试可能的追问与准备

| 追问方向 | 准备要点 |
|---------|---------|
| 为什么 RSSI 用中位数而非均值 | 中位数抗多径引起的离群点（RSSI 常呈重尾分布） |
| 卡曼滤波 Q/R 怎么调 | Q 大→信任模型→平滑但迟钝；R 大→信任测量→跟踪快但噪声大。可用 Allan 方差或试凑法 |
| MUSIC 分辨率受什么影响 | 阵元数 M 越多、快照 K 越多、SNR 越高，分辨率越高；两信源夹角越小越难分辨 |
| ESPRIT 为什么比 MUSIC 快 | 不需要全角度搜索，直接特征分解求解，O(M³) vs O(M²·N_θ) |
| 真实 BLE AoA 怎么获取 I/Q | 需要支持 AoA 的 BLE 芯片（如 nRF53 系列 + QM33110 天线阵列），通过 IQ 采样包络提取相位差 |
| 数字钥匙的安全性 | 中继攻击（relay attack）是核心威胁，AoA/UWB 的距离测量可辅助抗中继 |
